## How it is intended to work

* LAN control/files: pair phone and PC through existing launcher, then enable selected permissions in Windows Control Center. The PC and phone can exchange commands and files without a working Internet route if they can reach each other on LAN. Plain LAN HTTP is not encrypted; prefer a trusted network or Tailscale.
* Phone -> PC Internet: in Remote Control > Internet sharing, refresh built-in Tailscale, explicitly advertise the phone as an exit node for one hour. Approve the node in Tailscale admin console, restrict autogroup:internet access to authorized devices, select it in Windows Control Center using the existing Tailscale client. Requires a running AgentLink process, working tailnet, working Android userspace forwarding, admin approval. This is implemented in source but not verified on an actual phone. Advertisement is not proof of working packet forwarding. On expiry, withdraw default routes; on failure close the node. App restart clears previous exit preferences, does not resume an old grant.
* PC/VPS -> phone: select an approved, online exit node in Remote Control. Built-in tsnet's Server.Dial goes through the selected exit node. The new model relay is loopback-only, has a random 256-bit path token, GET-only, maximum two concurrent requests, accepts only trusted HTTPS Hugging Face model/catalog hostnames, checks redirects on the native caller, carries Range/Content-Range, and retains existing file size and SHA-256 verification. No implicit direct Internet fallback when the chosen node is unavailable. Native catalog now uses the same transport as downloads. This is app-specific, NOT device-wide Android traffic. Other Android apps require OS-level tethering or a system VPN client, and full system routing must be tested separately. For a device with no Internet path to the tailnet, use ordinary hotspot/ICS (Android tether settings and Windows hotspot/ICS buttons); Tailscale alone cannot bootstrap a disconnected device. There is no custom full-system VPN or generic unauthenticated LAN relay in this change.
* Windows Control Center: existing exit-node selection/advertisement and Russian translation retained; added explicit creation of desktop shortcut and on-demand LAN/Tailscale selected-route diagnostics. Launcher v14 limits four concurrent remote actions and prevents automatic updates from interrupting active actions. Local permission revocation blocks new actions, not already-started shell processes; arbitrary shell is not sandboxed.
