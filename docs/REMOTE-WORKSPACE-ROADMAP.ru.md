Владелец запросил весь перечень ниже. Это согласованный объём развития, а не утверждение, что функции уже готовы. Базовая ветка fix/agentlink-auth-guide, приложение 0.26.6 пока не выпущено. Не публиковать APK или merge без разрешения. Cheri, её модель, жесты и анимации оставить без изменений.

## P0: стабилизация и безопасность

1. Сначала npm ci, npm run typecheck, npm run check:versions, npm test; затем сборка и тест Android. Пройти весь CLAUDE.md и agent.md, включая 401, 503, bootstrap, i18n, темы, модельные ошибки, сайт и маскотов. Не удалять пользовательские изменения. Исправлять выявленные дефекты до добавления новых экранов.
2. Проверить src/lib/connection-identity.ts и src/stores/connections.ts: не отправлять старый пароль другому URL, очищать прежние маршруты и обнаруженный API, проверять активный и неактивный сервер, ошибку SecureStore, перезапуск, явную повторную авторизацию. Нужны интеграционные тесты, а не только pure helper.
3. ACP: session state привязать к connectionId + agentId + protocolSessionId, а не к глобальному activeConnection. Проверить открытие чата до загрузки соединения, изменение target/params, аутентификацию, отмену, разрыв сети, race при смене сервера. Список агентов обновляется в фокусе; не допускать перекрывающихся запросов и старых результатов.
4. Устранить потерю истории при переполнении логов, некорректную интерпретацию gap и бесконечные reconnect. Ограничение 4 процесса пока оставить по умолчанию, предложить настройку с пределом и предупреждением о ресурсах. Не снимать лимит без проверки нагрузки.
5. Перед использованием endpoint /git/inventory провести аудит доверенных репозиториев и git config (включая внешние фильтры, fsmonitor, symlink/junction, linked worktree и окружение). Только репозитории владельца, не недоверенные клонированные проекты. Ни shell interpolation, ни arbitrary command. Права на workspace локально на ПК, не из удалённого запроса. Доступ выключен по умолчанию. В Windows AGENTLINK_GIT_ROOTS разделяется ;, Linux/macOS — :. В установщике и автозапуске проверить передачу разрешений; добавить локальный удобный выбор корня. Не пытаться «защитить» запуск произвольного Git в недоверенном репозитории одной проверкой пути.
6. Не хранить API keys, пароли, секретные URL в журнале. Для будущего дискового кеша — шифрование, лимиты, очистка и контроль владельца; никакой скрытой телеметрии.

## P1: Git, worktree, несколько компьютеров

### Git workspace
- Экран проекта: текущая ветка, изменения staged/unstaged/untracked, diff по файлу, список веток, история коммитов, поиск.
- Прочитать porcelain -z безопасно, учитывая rename, пробелы, Unicode, Windows paths. Реализовать ограниченные read-only endpoints, затем операции stage/unstage/commit/switch/create branch. На каждую изменяющую операцию — явный выбранный сервер/репозиторий, подтверждение, блокировка конкурирующих операций и проверка свежего состояния.
- Push/pull только по настроенному remote, без передачи секретов на телефон; PR через официальный GitHub API/CLI с авторизацией владельца. Не автопушить, не force push, не reset --hard, не clean -fd. Diff preview и подтверждение перед удалением/откатом. Никакого shell от клиента.
- Worktree: git worktree list --porcelain -z, создать в отдельном каталоге внутри разрешённого корня от выбранного commit/branch, уникальное имя ветки, связать с задачей и агентом; показать path, branch, dirty, busy; remove только при отсутствии незакоммиченных изменений и активного агента, по подтверждению. Разные агенты работают в разных worktree. Merge/rebase только по подтверждению, конфликты не скрывать. Worktree не security sandbox.
- Ссылки: https://git-scm.com/docs/git-worktree и https://git-scm.com/docs/git-status

### Fleet: несколько ПК и VPS
- Сохранённые connections уже есть. Добавить обзор всех узлов, состояние, последняя связь, CPU/RAM, запущенные агенты, проекты и быстрый переход.
- Независимый клиент и auth на connectionId; адреса/пароли/проект/история/уведомления не смешивать. Устойчивый serverId с миграцией существующих записей, без зависимости от изменяющегося IP. Не выполнять команды на другом сервере при глобальном переключении.
- Отдельно различать offline, auth rejected, outdated launcher, backend down, agent unavailable. Тест: два устройства с одинаковыми session IDs, разные passwords; сеть пропала на одном — второй работает. Не опрашивать все узлы агрессивно; лимит параллелизма, backoff, polling только при необходимости.

## P2: продолжение сессий, делегирование и фон

### Продолжение сессий
- ACP версия и capabilities из initialize, поддержка session/list, session/load либо session/resume только при заявленной поддержке конкретного адаптера. Текущий протокол v1 — не предполагать v2 автоматически. Хранить provider session ID отдельно от bridge process ID. Пагинация, cwd, восстановление истории; при отсутствии возможности показать «не поддерживается», предложить ручной экспорт контекста без ложного восстановления.
- Восстановление после перезапуска launcher: безопасный каталог метаданных с ограниченными правами, журнал событий с ограничением размера/retention и redaction. Различать потерю процесса и доступность сохранённой сессии. Отдельно тест reconnect SSE и resume нового процесса. Не повторять prompt при неопределённом результате отправки — idempotency/request reconciliation.
- Документация: https://agentclientprotocol.com/ ; https://github.com/agentclientprotocol/agent-client-protocol/blob/main/docs/protocol/v1/session-setup.mdx

### Передача задач
- Кнопка «Передать агенту»: выбор целевого ПК, проекта/worktree, установленного агента, обзор пакета передачи до отправки. Пакет: цель, требования, сделано/не сделано, файлы/commit, результаты тестов, нерешённые вопросы, ограниченный выбранный контекст. Не переносить скрытые reasoning или секреты; не передавать весь чат автоматически.
- Сначала ручная передача, затем очередь/координатор по желанию. Source agent ID + target agent ID + handoff ID, состояния pending/sent/failed/accepted; подтверждение, запрет дублей, отмена. Агент использует собственный вход и квоту. Никакого обещания объединить квоты.
- Серверный durable queue хранит задания на ПК и переживает закрытие телефона; ограничение ресурсов, явно обозначать остановку/ошибку/разрешение, не повторять выполненное.

### Надёжные фоновые уведомления
- Сервер хранит event inbox со stable eventId и ack; телефон при reconnect догружает пропущенное. Push opt-in, FCM/self-hosted sender, уведомления ошибок/вопросов/permission/completed; пользователь может выключить категории. Существующий код getAndroidPushToken не означает, что серверный push доставляется.
- При Android Doze/смахивании/потере сети: уведомление по возможности, догрузка событий после открытия; не обещать доставку при force stop. Foreground service — только подходящий законный тип и явный пользовательский режим; Android 15+ ограничивает некоторые типы, нельзя считать SSE вечным. Никакого скрытого обхода OS. Действия approve/deny проверяют serverId, sessionId, requestId, срок и действительность запроса; устаревшие не исполнять.
- Тест Android API 34/35/36, Doze, battery saver, reboot, потеря сети, смахивание, разрешение уведомлений denied, повтор события, отменённый запрос.
- https://developer.android.com/develop/background-work/services/fgs/timeout

## P3: мониторинг моделей, лимитов и железа

- Карточка /hardware уже даёт базовую загрузку CPU (дельта ticks), RAM (os.freemem; не считать точным MemAvailable на Linux), storage (home filesystem), uptime. Уточнить метрики Linux (/proc/meminfo MemAvailable), Windows (доступная физическая память), VPS cgroup limits. GPU/VRAM: NVIDIA nvidia-smi (фиксированный аргумент, timeout, no shell), AMD/Intel — доступные платформенные API, неизвестно при отсутствии. Температура — только реальные сенсоры. Показывать источник и timestamp; не опрашивать чаще разумного.
- Model throughput: Ollama eval_count / eval_duration * 1e9 (наносекунды), prompt_eval_count отдельно. llama.cpp timings.predicted_per_second / prompt_per_second либо predicted_n/predicted_ms*1000. Метрики ответа от самого движка, разделить prefill и decode; TTFT отдельно от сети, время загрузки отдельно. Не считать количество чанков или символов токенами. Для streaming без timing — только явно обозначенная оценка по подтверждённым token counts; иначе «—». Подключить src/lib/model-metrics.ts к реальным ответам, UI в чате и Model Monitor. Бенчмарк запускается только по нажатию, ограничить max tokens, отмена.
- Quota: ACP usage_update — контекст, не подписка. Отдельно токены input/output/cached, context window, расходы API по проверяемому тарифу и квота/renewal только официально сообщённые. Не скрейпить cookies, не хранить аккаунтные секреты, не обещать «сколько осталось» там, где API не даёт. Не смешивать данные разных аккаунтов. Применять quotaFromReport, unknown состояние, timestamp.
- https://github.com/ollama/ollama/blob/main/docs/api.md
- https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md

## P4: рабочая среда на телефоне

### Редактор кода
- Существующий файловый браузер расширить. Открыть файл в CodeMirror 6 (кандидат; оценить RN WebView и лицензии) или другом локально встроенном редакторе, подсветка JS/TS/Python/JSON/HTML/CSS/Markdown, поиск, номера строк, undo, табы, клавиши для мобильного. Двоичные/слишком большие файлы read-only.
- Работать только внутри разрешённого repo/worktree. Сохранение атомарно, expected revision/hash; конфликт при параллельной правке агентом — diff и выбор, не затирать. Предпросмотр изменения, autosave opt-in. Не передавать токены и пароль в WebView. Изолировать JS-контекст редактора.
- Проверка UTF-8/BOM, CRLF/LF, Unicode paths, symlink, traversal, большой файл, права чтения/записи, потеря сети, два редактора.

### Предпросмотр сайта
- Определённый dev-server на компьютере, явное разрешение локального порта и ограниченный список разрешённых проектов, lifecycle start/stop, адрес через LAN/Tailscale или авторизованный proxy. Запрет произвольных URL/SSRF, cloud metadata, приватных сервисов, открытых интернет-туннелей по умолчанию. Предпочитать отдельный origin, не передавать Basic Auth AgentLink сайту, отключить bridge/file access/универсальный доступ, ограничить навигацию/permissions. Не использовать тот же WebView, что Cheri/терминал.
- Для static HTML локальный preview без доступа к секретам. Горячая перезагрузка/WebSocket только при корректном прокси. Тест Vite/Next/static, IPv4/IPv6, порт занят, relative assets, HMR, malicious page, redirects, auth isolation. Запуск произвольных команд только уже существующим утверждённым агентом/терминалом, не новым generic shell endpoint.

## P5: локальные модели непосредственно на Android

### Архитектура
- Отдельная вкладка «На телефоне», без обязательного ПК и OpenCode. Кандидат llama.rn (React Native bindings llama.cpp), альтернативно собственный JNI/NDK llama.cpp. Пин совместимой версии после проверки Expo 54 / RN 0.81.5, new architecture/bridgeless, arm64-v8a и gradle; проект llama.rn имел отдельные проблемы с этой конфигурацией, поэтому не добавлять зависимости вслепую. Сначала proof-of-concept CPU inference на маленьком GGUF, затем GPU/HTP только при подтверждённом backend. CPU fallback и ясный статус. Не обещать поддержку всех HF architectures.
- https://github.com/mybigday/llama.rn
- https://github.com/ggml-org/llama.cpp/blob/master/docs/android.md
- https://huggingface.co/docs/huggingface.js/hub/README

### Каталог и загрузка
- Поиск HF Hub моделей GGUF, фильтры task, language, architecture, quantization, license, размер файла, revision SHA, gated/private support только официальным токеном пользователя через защищённое хранилище. Проверить schema HF API. Показывать конкретные файлы, а не суммарный размер репозитория.
- Публичные модели можно скачивать без токена, gated — только при одобренном доступе. Не обходить ограничения, не исполнять remote code, не загружать pickle/скрипты. Выбор GGUF, валидация magic/version/metadata, разрешённый URL хоста HF с корректным redirect handling; токен не пересылать на неподтверждённый redirect. Pin revision, verify expected size/hash при наличии. Проверить license/terms перед скачиванием.
- Возобновляемые загрузки Range/ETag/If-Range, temporary .part, atomic finalize, прогресс/отмена, место для временных файлов, Wi-Fi-only option, очистка частичных данных; учитывать FAT/SAF, storage quotas, 4+GB file. Android WorkManager/подходящий foreground service с учётом лимитов ОС. Не обещать продолжение после force-stop.

### Рекомендации по железу
- Читать доступную RAM, ABI, SoC (если доступен), GPU/backend capabilities, свободное место, battery/thermal state. RAM total не равна доступной RAM. Использовать src/lib/local-model-fit.ts как консервативный начальный фильтр: GGUF file size + architecture-specific KV cache + scratch + OS reserve. Уточнить quantization/context, GPU shared memory; показывать «предварительная оценка», не гарантировать запуск.
- Начать с 1–3B моделей в Q4, затем 4–8B по доступной памяти; larger models only if measured fit. Названия конкретных моделей и версии получать из текущего каталога и проверять совместимость движка. Сортировать: скорость, качество для кода, память, лицензия, русский язык — без выдуманных benchmark scores.
- Режимы «экономичный/баланс/качество» с контекстом/threads/batch/accelerator. Термальный throttling, отмена при critical thermal/memory; один inference context по умолчанию, освобождать при выходе. Телефон не обязан выполнять полноценные функции Claude/Codex — сначала самостоятельный offline chat, потом явные tool permissions и отдельное локальное agent loop.
- Бенчмарк: фиксированный prompt + max new tokens, warm/cold, prompt t/s, decode t/s, TTFT, peak memory, температура только доступный сенсор, время/энергия по доступным измерениям. Не считать результат одной модели прогнозом для всех.
- Приёмка: телефон arm64 и эмулятор, 1–3B GGUF реально генерирует offline, прерывание, повторная загрузка, неверный checksum, мало памяти/диска, устройство перегревается, restart, gated denied, no network, удаление модели и reclaim, не тормозит чат и Cheri.
