Основная реализация уже сохранена в ветке `fix/agentlink-auth-guide`. **Не начинай с нуля.** Прочитай [agent.md](https://github.com/jainikdroid-bit/AgentLink/blob/fix/agentlink-auth-guide/agent.md) и [AGENTS.md](AGENTS.md).

- Рабочая ветка: `fix/agentlink-auth-guide`
- Сайт: `gh-pages`

## Неприкосновенные требования владельца

1. **Cheri / 3D-персонажа не менять.** Сохранить перетаскивание пальцем, pinch-масштабирование, прозрачность, размер, анимации, меню, позицию и отображение на всех экранах. Не менять FloatingCheri, нативную обработку касаний, настройки аватара, 3D-модель и её поведение. Если обнаружится посторонняя правка этих файлов, не включать её без согласования.
2. Авторизация должна быть максимально простой: новичок видит мастер, QR, код; IP, порт, пароль и прочие детали раскрываются по необходимости. Не отключать защиту для удобства.
3. Гайды: шаг за шагом, короткое основное действие и раскрываемое пояснение/решение ошибок на каждом шаге. Поддержать Windows, Linux/macOS, LAN и Tailscale; сохранять русский язык и все локализации.
4. Пользователь не хочет вручную диагностировать и выполнять промежуточные команды. Самостоятельно читать исходники, запускать тесты, исправлять найденное. Человеческий вход в Tailscale/провайдер, разрешение Android и реальные устройства могут потребовать владельца: точно обозначить блокер.
5. Не публиковать токены, пароли, pairingLink или логи с секретами; не открывать порт OpenCode в публичном интернете; не обходить авторизацию провайдера.

## 1. Получи рабочую ветку

В существующем checkout сначала `git status --short` и `git remote -v`. Не сбрасывай пользовательские изменения. При грязной рабочей копии используй отдельный worktree или checkout.

```sh
git fetch origin
git switch fix/agentlink-auth-guide
# Если локальной ветки ещё нет:
# git switch --track origin/fix/agentlink-auth-guide
git merge origin/main
git diff origin/main...HEAD --stat
```

Если ветка уже существует локально, сначала проверь её расхождение с origin и безопасно синхронизируй. На момент подготовки main опережал общую базу двумя коммитами README; рабочая ветка содержала те же правки. Не используй force push. Проверь конфликты, не отменяй чужую работу.

## 3. Обязательный аудит и доведение до готовности

### P0 — безопасность и авторизация

- `tools/launcher.js`, `tools/launcher.test.js`: проверить одноразовость кода, 10 минут, пять неверных попыток, HTTP 503 при отсутствующем пароле без расходования кода, единый username opencode. Проверить запуск сервера не только из launcher, но и из `tools/connect.js`: env пользователя не должен приводить к несовпадению логинов. Проверить обновление launcher v7.
- `src/stores/connections.ts`, `app/connection/[id].tsx`: тест сохранённого подключения должен брать сохранённый пароль из SecureStore только для того же endpoint. **Отдельный потенциальный дефект:** updateConnection при изменённом URL и пустом поле сохраняет прежний секрет и перестраивает клиент с ним. Устранить до релиза: новый endpoint не должен получать старые credentials автоматически, очистить/перепроверить старые метаданные маршрута (lanHost, launcherPort, tunnelTopic) при смене endpoint. Явное повторное введение пароля допускается. Добавить регрессионные тесты для активного и неактивного подключения, включая смену URL, слэши и порт.
- `app/connect.tsx`, `src/lib/pair-code.ts`, `app/pair-code.tsx`: различать 401/403, 503, неверный/просроченный код и сетевую ошибку; не предлагать включить Tailscale при отклонённом пароле. Проверить повторное сопряжение существующего сервера, отсутствие дублей, сохранение lanHost при вставке ссылки.
- Не выдавать пароль в логи, отчёты, route-debug или внешние ссылки. Проверить защиту чувствительных данных в диагностике и отображении ошибок.
- QR или код подтверждает доступ к компьютеру, но не вход в AI-провайдера. Не обещать, что исправление AgentLink устранит сбой qwen36-free. Диагностировать отдельно при наличии доступа к OpenCode; не запрашивать секреты в чате.

### P1 — мастер и интерфейс

- `app/guide.tsx`, `src/lib/guide.ts`: LAN 2 шага, Tailscale 3, правильный счётчик, назад, пропуск, QR и код. Отображаемая команда и копируемая команда должны совпадать. Проверить команды -Mode lan / --mode lan и реальное поведение установщиков.
- Важно для тестирования ветки: remote bootstrap scripts скачивают core с main. Проверять исправления из локального checkout (изучи скрипты и используй локальные tools/connect.js и зависимости), иначе тестируется старая версия launcher. Не меняй production URL на временную ветку в опубликованной инструкции.
- `app/connection/add.tsx`: мастер первым, ручная форма и помощь свёрнуты, расширенные настройки доступны. Проверить отсутствие тупиков при навигации и понятные подсказки. Существующая подсказка запуска на 127.0.0.1 сама по себе не даёт доступ с телефона; заменить на ссылку/пояснение о безопасной настройке через мастер. Не советовать открыть порт наружу.
- `app/session/[id].tsx`, `src/stores/events.ts`, `src/lib/useOverallStatus.ts`, `src/components/ConnectionStatus.tsx`: проверить компактную шапку, модель, поле ввода, статус retry и конечную ошибку. Живая SSE-связь не доказывает, что модель работает; не рисовать успешное выполнение при ошибке. Ограничить длинные ошибки, показать детали по нажатию, не раскрывать секреты. Проверить типы и вызовы всех компонентов.
- Все 11 языков: проверить i18n, особенно RU/EN, отсутствие сырых ключей и длинных обрезанных кнопок. Не меняй Cheri. Проверь её регрессию на устройстве.


Проверь APK в android/app/build/outputs/apk/release/, package id cc.agentlabs.opencode, версию, архитектуры, подпись и SHA-256. Не выдавай debug-подпись за официальную; не публикуй ключи подписи. Сборка и релиз — разные этапы.

Приёмка: чистая установка; обновление существующей установки с совместимой подписью; Windows + Android LAN и Tailscale; QR/код/ссылка; отказ с неверным паролем; восстановление после 401; провайдерная ошибка отдельно от сети; ручной endpoint без утечки старого пароля; чат и управление Cheri. Владелец уточнил: нужны именно **плавающие 3D-персонажи как Cheri**, не только 2D. Добавлены оригинальные полнотелые процедурные модели на Three.js — Byte (лиса-компаньон) и Orbit (робот-компаньон). Перед выпуском: обязательно запусти полный typecheck и npm test, затем node scripts/build-cheri3d.mjs, проверь наличие android/app/src/main/assets/companions3d/{byte,orbit}.html внутри APK, собери и протестируй Android. Проверить плавность, ориентацию, размер/кадрирование, потребление CPU и GPU; довести внешний вид и анимации до качества релиза. ## Расширение AgentLink: Remote Workspace (запрос владельца)

Обязательный объём и критерии приёмки: [ROADMAP](https://github.com/jainikdroid-bit/AgentLink/blob/fix/agentlink-auth-guide/docs/REMOTE-WORKSPACE-ROADMAP.ru.md).
- Реализована изоляция старого пароля при изменении URL: clearOldRoute/sameEndpoint, удаление секрета до сохранения нового адреса, сброс прежней LAN/tunnel/launcher/API метаинформации. Нужен тест реального SecureStore и гонок.
- ACP: открытый чат удерживает первоначальный target; позднее появление target запускает начальную попытку; permanent 401/403/404 прекращают reconnect. Список агентов обновляется раз в 15 с в фокусе, ответы устаревшего target не применяются. Проверить гонки и навигацию.
- Launcher v8: GET /hardware после Basic Auth, CPU по дельте ticks, RAM по os.freemem, диск home filesystem, uptime; карточка в app/agents.tsx. GPU/температура неизвестны, не подделывать показания. RAM на Linux требует более точного MemAvailable, VPS cgroups — отдельный источник.
- GET /git/inventory — экспериментальный read-only, opt-in AGENTLINK_GIT_ROOTS, canonical path boundaries, фиксированные аргументы Git, timeout, без shell. Скачивание git-workspace.js добавлено в установщики. UI, операции записи и создание worktree не реализованы. Аудит доверия Git config и тесты на реальных репозиториях обязательны.
- model-metrics.ts: Ollama/llama.cpp rates, context usage и provider-reported quota; ещё не подключены к реальному inference stream. local-model-fit.ts: консервативный фильтр по памяти/диску, runtime overhead обязательно оценить. Native LLM engine, HF загрузки и UI не реализованы.
- Добавлены unit tests. В JS-изоляте непосредственно по полученным исходникам (удалены TS-аннотации, подставные часы/система для hardware) проверены 9/9 сценарных утверждений: endpoint identity и очистка, расчёт скоростей, неизвестные значения, квота/контекст, модель fit, CPU/disk. Полный node:test, Git integration, typecheck, Gradle, Android и реальные запросы не запускались.
- Остальные запрошенные функции расписаны в roadmap: Git + worktree, resume с capabilities, multi-host Fleet, лимиты, мониторинг, handoff, фоновые события, редактор и preview, HF GGUF download + native inference. Делать итерациями, не выдавать требования за реализацию. Cheri не менять. Не публиковать и не merge без разрешения.
